# STUDY SYSTEM TEMPLATE

> A study system = a study stack + the rules, functions, and mechanisms that make it repeatable.

---

## 1. STUDY STACK

> The components the system uses.

| Layer | What it includes | Example |
|---|---|---|
| **Tools** | Apps, software, physical tools | Obsidian, Anki, notebook |
| **Methods** | Learning techniques and frameworks | Analogical encoding, retrieval practice, case-based learning |
| **Resources** | Source material, feedback sources, environments | Domain texts, expert feedback, real cases |

---

## 2. SYSTEM RULES

> Rules that govern how the stack is used. These turn isolated tools and methods into a coherent process.

| Rule | What it means |
|---|---|
| **Domain Structure Rule** | Match methods to the level of structure in the domain. |
| **Sequence Rule** | Use stack components in a defined order, not randomly. |
| **Feedback Rule** | Feed outputs back into the stack for calibration. |
| **Analogical Rule** | Always compare at least two cases, examples, or subdomains. |
| **Knowledge Type Rule** | Match technique to the dominant knowledge type. |

---

## 3. SYSTEM PROCESSES

> What the stack does when rules are applied. Each mechanism uses specific stack components.

| Mechanism | Stack Used | Output |
|---|---|---|
| Domain Mapping | Tools + Resources | Domain map / overview |
| Case Exploration | Tools + Methods | Case notes |
| Cross-Case Comparison | Methods + Resources | Analogical schemas |
| Feedback Calibration | Methods + Feedback sources | Error log / updated model |
| Synthesis | Tools + Methods | Integrated domain knowledge |

---

## 4. WORKFLOW / SESSION CYCLE

> The repeatable loop that runs the system. Or a timed schedule session.

| Stage | Action |
|---|---|
| Pre-session | Review domain architecture and current map |
| Active session | Run stack mechanisms according to system rules |
| Post-session | Update tools, notes, and error log |
| Next session | Choose next subdomain or comparison case |

---

**Core Rule:**  
The stack provides capability. The rules and mechanisms turn that capability into a system. The workflow keeps it running.
