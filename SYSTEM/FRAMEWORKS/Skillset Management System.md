The SMS is a system for keeping huge set of skills almost ready, without having to be an expert in all of them at once.

---
## 1. BARE BONES
### 1.1 THE FOUR SKILLSET STATES:
- **Active** - Ready right now, under stress. (You practice it a lot)
- **Dormant-Warm** - Usable after 30 minutes warmup (You keep it lightly refreshed)
- **Dormant-Cold** - Needs 4-48 hours of focused reactivation to be useful. (You leave it sleeping, but you have plans to wake it fast.)
- **Archived** - You only remember the big picture. Full retraining needed but it will still be far quicker than learning from scratch.
The ideal goal is to keep most skills in Dormant-Warm or Dormant-Cold, and only a few Active.

### 1.2 **THE SKILL ONTOLOGY**:
This is how skills are organised into primitives(atomic sub-skills) and composites(integrated routines). They are also categorised by cognitive type and potential for transfer. it’s the **structured map of everything you know and can do**—a living taxonomy that tells you not just what a skill _is_, but what it’s _made of_, what _type_ of knowledge it relies on, and how it _connects_ to every other skill in your repertoire.

| SKILL ENTRY METADATA FIELD                                       |                                                                                                                                   |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Name                                                             | Concise label                                                                                                                     |
| Type                                                             | Cognitive taxonomy category(Declarative, Procedural-Cognitive, Procedural-Motor, Perceptual-Cognitive, Metacognitive)             |
| Level                                                            | Primitive or Composites                                                                                                           |
| Primitives                                                       | (if composites) the atomic-subskills it requires                                                                                  |
| Composites                                                       | (if primitives) which higher-order skills needs it                                                                                |
| Cross-Domain Links(e.g is it Tradecraft, Military Strategy, etc) | tagged connections to other skills in the ontology (with a brief note on _why_ they’re linked—this is the forced analogy insight) |
| Current State                                                    | Active, Dormant-Warm, Dormant-Cold, Archive.                                                                                      |
| Forgetting Curve                                                 | How fast does it decay                                                                                                            |
| Maintenance Plan                                                 | Pointer to the protocol (keystone drill, spaced retrieval schedule, etc.)                                                         |
| Reacquisition Plan                                               | Pointer to the schema map and error-priming diagnostic                                                                            |

The ontology is not just a list; it’s a **graph**. Skills link to other skills through explicit relationships like “shares deep structure with”, “is a prerequisite for”, “is the domain-specific application of”, “can be transferred from”, and “is analogous in function to”. This graph is what allows the “derive, don’t learn” shortcuts.

**1.2.1 - Cognitive Types**

| Cognitive Types      | Description                                     | Examples                                                                                                              |
| -------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Declarative          | Facts, Concepts, Laws, Formulas                 | Penal code sections, agency manual procedures, etc.                                                                   |
| Procedural-Cognitive | Mental Algorithms, Planning, Analysis           | Threat modeling, psychological profiling, constructing a legal arguement, etc                                         |
| Procedural-Motor     | Physical Execution Skills                       | Magazine change, knife-disarming flow, throwing mechanics, urban movements over obstacles.                            |
| Perceptual-Cognitive | Pattern Recognition, and Sensory Interpretation | Surveillance detection, micro-expression reading, network traffic anomaly spotting, terrain reading for orienteering. |
| Metacognitive        | The Control System                              | Goal setting for study session, error analysis during debrief, analogical mapping between domains.                    |
Every skill you have gets tagged with exactly one of these. But the magic is that many _composites_ blend types. A CQB entry is primarily Procedural-Motor, but it also has a Perceptual-Cognitive component (reading the room) and a Procedural-Cognitive component (decision tree: shoot/no-shoot). In the ontology, the composite “Dynamic CQB Entry” would link explicitly to primitives across these types.
### 1.3 MAINTENANCE PLAN
You can write a maintenance plan that allows you to maintain a skill without daily practice.
- **Keystone Drills** - one activity that touches 4–5 skills at once (e.g., a “shadow op” city walk combines surveillance, fieldcraft, and psychology).
- **Spaced recall with linking** — whenever you review a legal rule, you mentally connect it to a CQB scenario. This makes the memory stick and builds your web of connections.
- **Mental rehearsal with physical feeling** — vividly imagining a motor skill while tensing the relevant muscles keeps the brain pathways alive.
There are other ways to possibly write or do a maintenance plan, it is up to the user to build such plan utilising different study techniques.

### 1.4 REACQUISITION PLAN
When you suddenly need a skill that’s been asleep:
1. **Schema Reactivation (15–30 min):** Re-read the high-level skill ontology map/cheatsheet for that domain. Just the big structure.
2. **Self-Test First (1–3 hours):** Try to do the skill cold without help, fail, then check a short guide. The struggle primes your brain for rapid recovery.
3. **Realistic Micro-Drill (1–4 hours):** Practise it in a stressful, mission-like setting to re-automate it.
4. **Integration Test (1 hour):** Combine it with two other skills in a mini-scenario to make sure it’s now fully plugged back in.

A Dormant-Cold skill can be ready to use in 6–8 hours total.

---
### 1.5 The Self-Watching Loop
Constantly ask:
- **Forecast:** What skills will I need in the next month?
- **Monitor:** Is a skill feeling rusty right now?
- **Evaluate:** Did my wake-up plan work? Can I make it shorter?
- **Regulate:** If something is decaying faster than expected, do a quick drill within two days.
### 1.6 NOTES
You can only keep 3–4 skills truly Active and about 8–10 Dormant-Warm. The rest must sleep. Your body still needs basic fitness, and constantly reshaping your mind is tiring, so you need a stable core identity and rest.
