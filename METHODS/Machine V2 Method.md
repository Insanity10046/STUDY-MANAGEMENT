# Machine Method V2
## Theoretical Basis
Built on **schema construction**, the **testing effect**, **interleaving**, **desirable difficulties** (Bjork & Bjork), **cognitive load management**, **scaffolding/fading**, and **spaced repetition**. Core loop:

> Schema Induction → Interleaved Retrieval Practice → Immediate Corrective Feedback → Schema Refinement → Scaffold Fading → Criterion-Referenced Assessment → Consolidated Recall Summary

---

## Phase 0 — Schema Induction (Broad Scaffold)

Build a coarse **mental schema** of the whole domain first — top-down, not bottom-up. Target deep structure(pillars of the domain or foundations, e.g for laws it would be legal research, writing, and arguement the 3 pillars of legal studies), not surface facts(topics of the domain).

**Example (Algebra)**:
> Algebra is preserving equivalence while isolating unknowns.  
> Algebra focuses on the mathematical statements(equations, expressions, inequalities, systems) all of which have structures in them(geometric structures).  
> Equations use inverse operations, inequalities add sign-reversal rules, system reduces to one equation via substitution/elimination, and expression are simplifed not solved.

This is a low-resolution **advance organizer** (Ausubel). Per **cognitive load theory**, avoid early elaboration — it adds extraneous load without aiding schema formation. Refine later, via error feedback.

---

## Phase 1 — External Scaffolding

Externalize the schema into two supports (**cognitive offloading**):

1. **Condition–action rules**, e,g(cheat-sheet):
> IF dividing by a negative → flip inequality.  
> IF both equations isolate the same variable -> use substitution.  
> IF no equation/inequality -> only simplify.
2. **Concept map**, showing relational structure (**dual coding**: spatial + verbal). e,g(mind-maps):
> Algebra -> Equations, Inequalities, Systems, Expressions  
> Systems -> Substitution, Elimination  
> Inequalities -> Sign Reversal, Inverse Operations

These reduce load during early interleaved practice.

---

## Phase 2 — Interleaved (Mixed) Retrieval Practice

Use **interleaving**, not blocked practice: mix all subtopics from the start. Forces **discrimination learning** and counters the **illusion of competence** (related to the **Dunning–Kruger effect**).

Per item:
- Free recall attempt, 30–60 seconds, before consulting(cheatsheet) supports.
- Consult scaffolds(cheatsheet) only if retrieval fails.
- Solve, then apply immediate corrective feedback.
- For concept map, draw it before or after practice, compare and add missing gaps.

Leverages the **testing effect** and **generation effect** for more durable, transfer-ready encoding.

---

## Phase 3 — Compressed Feedback Loop

> Attempt → Outcome → Compare against schema → Detect error → Update schema → Repeat

An **error-driven learning** cycle — update magnitude tracks the size of the mismatch.

**Compress feedback** artificially when real-world feedback is slow: model solutions, worked examples, expert critique, simulations, after-action reviews, proficiency probes.

**Refine at point of error**, not in a separate review session — consistent with the **hypercorrection effect** where you update the cheat-sheet, mind-maps, or the summary.

---

## Phase 4 — Scaffold Fading

Avoid scaffold dependence, which blocks **automaticity**. Fade in stages (**cognitive apprenticeship** model — Collins, Brown & Newman):

1. Remove worked examples.
2. Remove minor details.
3. Remove rule labels; keep triggers.
4. Remove triggers; keep headings only.
5. Remove the scaffold entirely.

**Reconstruct from memory:** periodically redraw the concept map unaided, compare, correct gaps — retrieval practice applied to structure, not just facts.

---

## Phase 5 — Procedural Consolidation

Convert declarative knowledge ("that") into procedural knowledge ("how") — the **ACT-R** distinction (Anderson).

- **Well-structured domains:** timed mixed problem sets, symbol drills, proofs with instant checking — builds **automaticity** via **deliberate practice**.
- **Ill-structured domains:** simulation/role-play (moot court, negotiation), since fluency depends on judgment, not just rules.

After each simulation, run an **after-action review**: What did I do? Why? What cue did I miss? What would I change? What rule updates follow?

---

## Phase 6 — Mastery Check

Closed-book, interleaved, timed, no aids — a **summative** check for unaided, **transfer-appropriate** retrieval. Fail → return to Phases 2–5; pass → proceed.

---

## Phase 7 — Consolidated Recall Summary

Write the final summary only after mastery — a **retrieval artifact**, generated from memory, which is itself a retrieval event.

**Include:**
1. **Structural core** — the domain's few generative principles.
2. **High-yield rules** — condition–action rules, exceptions, boundary conditions driving most correct performance.
3. *(Ill-structured domains)* — discriminating case features, decision trees, mistake logs.

Keep it compact and durable — an efficient long-term schema for retrieval, not learning.

---

## Phase 8 — Spaced Review

Use the summary for **spaced repetition**, per the **spacing effect** and **forgetting curve** (Ebbinghaus):

- Review on an expanding schedule.
- Keep interleaving topics in future practice.
- Periodically reconstruct the schema from memory to catch decay early.

---

## Governing Principles (Summary)

| # | Principle | Cognitive-Science Basis |
|---|---|---|
| 1 | Don't over-elaborate the initial schema | Cognitive load theory |
| 2 | Interleave from the start | Interleaving; discrimination learning |
| 3 | Retrieve before consulting aids | Testing effect; generation effect |
| 4 | Fade scaffolds progressively | Cognitive apprenticeship; automaticity |
| 5 | Compress and force feedback loops | Error-driven learning; hypercorrection effect |
| 6 | Simulate for ill-structured domains | Situated/procedural learning |
| 7 | Write summaries only post-mastery | Consolidation; retrieval-based encoding |
| 8 | Save final notes for spaced review only | Spacing effect |

---

## Trade-off Analysis

| Pros | Cons |
|---|---|
| Rapid, integrated schema formation | Requires discipline to fade scaffolds on schedule |
| Deep relational understanding | Early interleaved practice feels harder |
| Mitigates illusion-of-competence | Compressed feedback takes upfront effort |
| Works across well- and ill-structured domains | Ill-structured domains still need simulation design |
| Final artifact is compact and durable | Fewer intermediate notes early on |
